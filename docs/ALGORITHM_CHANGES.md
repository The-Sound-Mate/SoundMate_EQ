# 알고리즘 변경 · 치명적 오류 기록

이 파일은 **SoundMate EQ 의 소리가 달라지는 변경**과 **치명적 오류**만 누적 기록한다.
리팩터링·오타·코드가 그대로 말해주는 것은 적지 않는다.

기록 규칙
- 알고리즘 변경: **무엇이 이전→이후 / 왜 / 음색 영향 / 되돌리는 법**
- 치명적 오류: **증상·재현 / 근거(실측 수치) / 조치**
- 주장에는 수치를 붙인다. 이 프로젝트는 "먹먹하다" 같은 증상을 배율 실측으로 잡아온 이력이 있다.

최신 항목이 위로 온다.

## [2026-09-20] v0.1.1 — 장르 제거 + 취향 가중 보정

곡을 기준 스펙트럼과 비교해 **편차를 재고, 그 편차를 사용자 취향 방향에 따라 비대칭으로 보정**하는 단일 제어식으로 전환. 장르는 커브 산출에서 완전히 빠진다.

### 치명적 오류

#### E1. 기준 스펙트럼을 밴드별 타깃으로 쓰면 4곡 표본 잡음이 전 사용자 보정 목표가 된다

**증상·재현**
`LocalCurve::RefSpectrum()` 은 31밴드 상대 파워 기준 스펙트럼이다. 지금까지는 `EnergyChangeDb()` 의 **스칼라 에너지 합**에만 쓰여서 국소 굴곡이 상쇄됐다. v0.1.1 제어식은 이걸 **밴드별 타깃**으로 쓰므로, 배열의 모든 요철이 그대로 보정 목표가 된다.

**근거 (실측)**
출처가 `mood_log.jsonl` 의 **4곡**(발라드/재즈/K-pop/첼로) 평균이다 (`LocalCurve.cpp:245-249` 주석이 "잠정치"라고 명시). dB 변환 후 자기 ±2밴드 추세 대비 이탈량:

| Hz | raw dB | ±2밴드 평활 | 이탈 |
|---|---|---|---|
| 20 | -24.16 | -20.29 | **-3.87** |
| 25 | -20.74 | -17.91 | -2.83 |
| **40** | -10.76 | -14.69 | **+3.93** |
| 200 | -9.63 | -11.22 | +1.59 |
| 10000 | -26.87 | -28.05 | +1.19 |
| **12500** | -29.20 | -31.51 | **+2.31** |
| **20000** | -42.58 | -35.09 | **-7.49** |

40Hz 범프는 표본 4곡 중 일부의 베이스라인, 20kHz 급락은 코덱 컷오프가 평균에 섞인 것이다. 그대로 타깃으로 쓰면 40Hz 범프가 없는 곡은 최대 `α×3.93 ≈ 2.8dB` 를 부스트받고, 20kHz 에 실제 내용이 있는 곡은 `α×7.49 ≈ 5.2dB` 를 깎인다.

**조치 (2중)**
1. `LocalCurve::ReferenceShapeDb()` 신설 — dB 변환 후 **±2밴드 이동평균**을 적용한 형상을 반환. 40Hz·12.5kHz 아티팩트 소멸, 넓은 기울기는 보존.
2. 양 끝단은 `ComputeTasteDelta` 의 기존 `firstActive/lastActive ±2` 가드가 이미 0 으로 막는다 → 20Hz·20kHz 무효화.

`EnergyChangeDb()` 는 계속 **원본** 배열을 쓴다 → `Generate()` 출력 불변 → GATE 1 영향 없음.

**남은 부채**: 표본이 4곡뿐인 건 그대로다. 로그가 쌓이면 재산출할 것. 평활은 잡음을 덮을 뿐 표본을 늘려주지 않는다.

#### E2. 적응 델타 가산에만 origin 가드가 빠져 있다 — 수동 모드 이중 적용

**증상·재현**
`MainWindow.cpp:532-534` 의 델타 가산이 `m_eqOrigin` 을 보지 않는다.

```cpp
if (m_adaptiveDelta.size() == master31.size())
  for (size_t i = 0; i < master31.size(); ++i)
```

같은 블록의 나머지는 전부 `Manual/Preset/Flat` 을 제외한다 — `NormalizeForPlayback`(`:551`), 슬라이더 리드백(`:2572`), 수동 인계(`:2662`). 이 세 줄만 빠져 있다.

더 나쁜 건 `:2668` 이 첫 슬라이더 조작 때 `m_eqGains31Master = m_eqDisplay31` 로 **델타가 이미 섞인 값을 SSOT 에 구워넣는데**, 그 뒤에도 `:532` 가 델타를 또 더한다는 점이다. 곡이 바뀔 때까지 이중 적용이 유지된다.

**근거**
`m_adaptiveDelta` 는 곡 변경(`:1391-1400`)에서만 `.clear()` 된다. 수동 전환 시 클리어하는 경로가 없다. `AdaptiveCurve.h:180-184` 의 "여기에 델타가 섞인 값을 저장하면 델타가 또 얹혀 누적된다"는 주석이 정확히 이 상황을 경고하고 있었으나 가드가 실제로는 없었다.

**조치**
`:532` 에 같은 3-way 가드를 추가한다. v0.1.1 에서는 필수다 — 새 제어식의 델타는 `-α·편차` 로 의미가 "taste 기준 상대량"이 되어, 수동 커브에 더하면 명백히 틀린 값이 된다.

#### E4. 기본 스마일 커브가 지금까지 전 사용자에게 걸려 있었다

**증상·재현**

|---|---|---|---|

즉 **23개 장르 테이블은 프로덕션에서 죽은 코드였고, 모든 사용자는 스마일 커브를 받고 있었다.**

**조치**

**음색 영향: 전 사용자.** 저역과 초고역이 각각 약 3dB / 2.5dB 차분해지고 중역이 상대적으로 올라온다 (중립화 후 기준). 릴리즈 노트에 반드시 명시할 것.

### 알고리즘 변경

#### A1. 장르 축 제거 — `Generate()` 의 첫 인자를 무시한다

**무엇이 이전→이후**
이전: `LocalCurve::Generate(genre, tendency)` 가 23개 장르 테이블을 조회하고, 못 찾으면 `DefaultGenre()` 스마일 커브를 깔고, 그 위에 설문 성향을 더했다.
이후: 장르 조회 자체가 없다. 커브는 **설문 성향만**으로 만들어진다. 봉인 테이블 `kDefaultBlob`(슬롯 0x0080)·`kGenreBlob`(0x0100~0x02DF, 23×32)과 `DefaultGenre()` / `GenreTable()` / `RGenre` / `EGenre` / `SealGenres` / `UnsealGenre` 를 삭제했다.

**시그니처는 그대로 둔다.** `Generate(const std::string& genre, ...)` 의 첫 인자를 받아만 놓고 쓰지 않는다. 이유는 게이트다 — GATE 1(`curve_equiv`)이 **40개 장르 문자열 × 2054 성향 = 82,160 케이스**를 계속 스윕하면서 이제는 "장르가 `LocalCurve.cpp` 와 `tools/localcurve_ref.cpp` 양쪽에서 **똑같이 무시되는지**"를 검증한다. 인자를 지웠으면 이 축이 통째로 사라졌을 것이다. 호출부(`MainWindow.cpp:776`)와 `curve_equiv_main.cpp` 도 무수정으로 남는다.

**왜**
E4 가 근거다. 장르 테이블은 프로덕션에서 단 한 번도 동작한 적이 없다 (`track` 284행 중 genre 보유 0행). 그리고 v0.1.1 제어식은 곡의 **실측 스펙트럼**을 직접 본다 — 장르 라벨은 "이 곡이 어떻게 생겼는가"의 저해상도 대리 변수였을 뿐이고, 실측이 있으면 대리 변수는 필요 없다. iTunes 장르 문자열의 품질·커버리지에 의존하던 경로가 통째로 사라진다.

**음색 영향**
전 사용자. E4 에 적은 대로 저역 −3dB / 9kHz 이상 −2.5dB / 500Hz +1.5dB 만큼 스마일이 걷힌다.

**되돌리는 법**
`git revert` 로 `LocalCurve.cpp` / `tools/localcurve_ref.cpp` 두 파일을 되돌리면 된다. 삭제된 테이블은 히스토리에 그대로 있다. 되돌릴 때 **두 파일을 반드시 같이** 되돌려야 GATE 1 이 통과한다.

#### A2. 따로 돌던 두 제어 루프를 단일 제어식으로 통합

**무엇이 이전→이후**

이전 — 두 법칙이 서로 모르는 채 겹쳐 있었다.
1. `LocalCurve::Generate` 가 설문으로 정적 커브를 만든다 (곡과 무관).
2. `AdaptiveCurve::ComputeDelta` 가 곡의 스펙트럼을 **자기 자신의 ±2밴드 추세**와 비교해 튀는 밴드를 깎는다 (취향과 무관).

이후 — 하나의 식이다.

```
refDb[b] = 10·log10(RefSpectrum[b])                    // ±2밴드 평활 (E1)
dev[b]   = (measured[b] - refDb[b]) - offset
offset   = 라우드니스 가중 평균( measured - refDb )      // 재생 음량 제거
dev'[b]  = sign(dev)·max(0, |dev| - kTasteDeadzoneDb)   // 소프트 데드존
agree[b] = tanh( dev[b]·taste[b] / kAgreeScaleDb² )     // +1 동조, -1 상충
α[b]     = kAlphaAgree + (kAlphaOppose - kAlphaAgree)·(1 - agree[b])/2
corr[b]  = taste[b] - clamp( α[b]·dev'[b], ±kDevClampDb )
```

`ComputeDelta` 는 남기지 않고 제거했다. 죽은 두 번째 제어 법칙을 남기면 나중에 어느 쪽이 진짜인지 헷갈린다. 새 API 는 `AdaptiveCurve::ComputeTasteDelta(measuredDb, usable, freqs, taste31)` (`AdaptiveCurve.h:188`).

신규 상수 (`AdaptiveCurve.h:80-95`):

| 상수 | 값 | 의미 |
|---|---|---|
| `kAlphaAgree` | 0.25 | 편차가 취향과 **같은** 방향 — 곡의 개성을 보존 |
| `kAlphaOppose` | 0.70 | **반대** 방향 — 싫은 건 확실히 깎는다 |
| `kAgreeScaleDb` | 3.0 | 동조/상충 판정의 부드러움 (작으면 하드 스위치가 되어 이웃 밴드에 계단) |
| `kTasteDeadzoneDb` | 1.5 | 이만큼의 편차는 '곡의 개성'으로 보고 건드리지 않는다 |
| `kDevClampDb` | 5.0 | 편차 보정량 상한 (구판 `kDefaultClampDb` 와 같은 값) |

**MainWindow 합성 코드는 무수정이다.** `delta = corr - taste = -clamp(α·dev')` 이므로, 기존 한 줄 `master31[i] += m_adaptiveDelta[i]`(`MainWindow.cpp:544`, `master31 == taste`)가 `corr` 를 정확히 복원한다. SSOT / 수동 가드 / 2초 전환 / 3초 평활 전부 그대로다. 대신 α 계산에 `taste` 가 필요하므로 엔진에 주입한다 — `AdaptiveEngine::SetTasteCurve()`(`AdaptiveEngine.h:141`), 호출 `MainWindow.cpp:1366`.

**사용자가 적어준 식과 의도적으로 다르다.** 사용자 원식은 `보정 = -α·(편차 - 목표)`, 채택식은 `보정 = 목표 - α·편차`. 차이는 `목표·(1-α)` 다. 원식을 그대로 쓰면 **평균적인 곡(편차 0)에서 설문 취향이 절반 이하로 줄어든다** — `bass_heavy` 를 고른 사람이 +4dB 대신 +1.9dB 만 받는, 설문이 조용히 약해지는 회귀다. 취향 항의 가중치를 1 로 고정하면 사라지고, 사용자가 든 예시 5개는 채택식에서 전부 성립한다.

**설문 전에는** `taste` 가 비어 `agree = tanh(0) = 0` → `α = 0.475` → 순수 기준 정규화가 절반 강도로 걸린다.

**음색 영향 (실측)**
같은 곡, 취향만 뒤집었을 때:

| 밴드 | taste | 동조 시 corr | 무취향 corr | 상충 시 corr |
|---|---|---|---|---|
| 12.5kHz | +3.47 | **+2.78** | -1.17 | **-5.11** |
| 63Hz | -2.67 | **-1.72** | +1.68 | **+5.09** |

사용자가 든 예시 두 개가 그대로 재현된다:
- 밝은 곡 + `treble_warm` → 12.5kHz taste −4.22 → **corr −8.38** ("고음이 싫은데 고음이 큰 경우 줄여주고")
- 저역 약한 곡 + `bass_heavy` → 63Hz taste +2.20 → **corr +6.53** ("저음 약한 곡 + 저음 좋아함")

전체적으로 **평균 렌더 스팬 잔존이 96.7% → 211.7% (2.2배)** 로 커진다. EQ 가 확실히 세게 걸린다는 뜻이다. `NormalizeForPlayback` 후 에너지 예산은 1.50dB 를 그대로 지키므로 리미터 위험은 없지만, **체감 변화가 크므로 릴리즈 노트에 E4 와 나란히 적어야 한다.**

**되돌리는 법**
α 두 값만 낮추면 강도가 준다 (`kAlphaOppose` 0.70 → 0.5 가 1차 후보). 제어식 전체를 되돌리려면 `AdaptiveCurve.h/.cpp` + `AdaptiveEngine.h/.cpp` 를 함께 revert — `MainWindow` 는 손댈 필요 없다.

#### A3. 서버 커브(`curve31`)를 클라이언트가 무시한다

**무엇이 이전→이후**
이전: `resolve-track` 이 돌려준 `curve31` 이 있으면 그걸 **우선** 썼고, 없을 때만 `LocalCurve` 로 폴백했다.
이후: 항상 `LocalCurve::Generate("", userPref)` (`MainWindow.cpp:776`). 멤버 `m_serverCurve31` 은 남겨 뒀다 (`:1513` 에서 계속 채워진다) — 되돌리기 쉽게.

**왜**
서버 `curve.ts` 는 장르+성향으로 커브를 만든다. 여기를 v0.1.1 에 맞춰 고치면 **이미 설치된 v0.0.2 / v0.1.0 클라이언트의 음색이 즉시 바뀐다.** 외부 영향이라 승인 없이 배포하지 않는다. 그래서 이번 브랜치는 클라이언트가 무시만 하고, 서버는 무변경·무배포(`CURVE_VERSION` 2 유지). v0.1.1 이 퍼진 뒤 `curve.ts` 를 맞추고 3 으로 올린다. `resolve-track` 의 나머지 기능(제목/아티스트/아트워크 정규화)은 계속 쓴다.

**부작용**: 커브 산출식이 서버에만 있다는 보안 이점이 이 버전에선 사라진다. 다만 `LocalCurve` 는 원래 폴백으로 바이너리에 봉인된 채 들어 있었으므로 **새로 노출되는 정보는 없다.**

**되돌리는 법**: `MainWindow.cpp:762-776` 세 줄. 서버 쪽은 건드린 게 없으니 되돌릴 것도 없다.

#### A4. GATE 2 의 커브 상한 기준을 `|corr| ≤ 12dB` 에서 비대칭 설계 상한으로 교체 — **계획서에서 벗어난 부분**

**무엇이 이전→이후**
계획서(§6-2)는 "상한: `|corr| ≤ 12dB` (LocalCurve 클램프 범위 내)" 를 게이트 조건으로 적었다. 구현하면서 이 조건이 **증명 불가**임이 드러나 다음으로 바꿨다:

```cpp
const float kBoostCeilDb = kSoftKneeDb + kSoftKneeRangeDb + kDevClampDb + 6.0f;   // = +17.0
const float kCutFloorDb  = -(kBandClampDb + kDevClampDb + 1.0f);                  // = -18.0
```

**왜**
`corr = taste - clamp(α·dev', ±5)` 이고, `taste` 자체의 범위가 부스트와 컷에서 **비대칭**이다:
- 부스트는 `SoftKnee(g) = 3 + 3·tanh((g-3)/3)` 로 포화해 약 **+6dB** 에서 멈춘다.
- **컷은 소프트니를 타지 않는다.** `kBandClampDb = 12.0` 까지 그대로 내려간다.

따라서 `|corr| ≤ 12` 는 컷 쪽에서 정상 동작만으로도 깨진다 (−12 − 5 = −17 이 합법). 계획서의 12dB 는 이 비대칭을 놓친 값이었다. 게이트가 틀린 조건으로 초록/빨강을 내면 게이트가 아니라 잡음이므로 여기서 바로잡았다.

**실측**: 정규화 전 최대 부스트 **+8.34dB** (한계 +17.0), 최대 컷 **−10.57dB** (한계 −18.0). 둘 다 여유가 크다. 최대 델타는 정확히 **5.00dB** — `kDevClampDb` 클램프가 실제로 물린다는 증거.

**음색 영향**: 없다 (게이트 조건 변경이지 신호 경로 변경이 아니다).

**되돌리는 법**: 되돌리지 말 것. 12dB 로 되돌리면 게이트가 정상 동작에서 실패한다.

#### E6. 가장자리 보호가 이진 차단이라 경계에 3.6dB 계단이 남았다

**증상 · 재현**
비발디 「사계 - 여름 3악장」(유튜브, 해석 실패 곡) 재생 중 EQ 화면에서 저역 슬라이더 하나가 이웃과 뚝 떨어져 **툭 튀어나와 보인다**. 사용자 보고: "너무 부드럽지 않게 툭 튀어 나와 있는거 있긴하네".

**근거 — 실측 (2026-09-20 20:42:40, 루트 `config.txt`)**

| Hz | 20 | 25 | **31** | 40 | 50 | 63 | 80 |
|---|---|---|---|---|---|---|---|
| dB | +3.76 | +3.75 | **+7.35** | +7.24 | +7.01 | +5.81 | +3.74 |

25Hz → 31Hz 사이 **+3.60dB**. 고역 끝에도 같은 것이 있다 — 12.5k `-0.32` → 16k `-0.90` = **-0.58dB**.

이것이 취향 커브의 형상이 아니라는 근거: 저역에 걸리는 도형은 `kBassBlob` / `kVolumeBlob` 의 **저역셸프뿐**이고(`LocalCurve.cpp:303-307, 342-349`), 셸프 합은 주파수가 내려갈수록 단조 증가한다. 예로 `bass_heavy` = LowShelf(100Hz, +4.0, 1.2) 는 20Hz 에서 +3.988, 31Hz 에서 +3.942 로 **차이가 0.05dB** 다. 관측된 `20/25Hz < 31Hz` 는 취향 커브만으로는 나올 수 없는 형상이므로, 3.6dB 전부가 적응 델타다.

**원인**
`AdaptiveCurve.cpp` 3~5단계가 가장자리를 **이진(0/1)으로** 잘라냈다.

```cpp
if ((int)i < firstActive + kSmoothHalfWidth ||
    (int)i > lastActive - kSmoothHalfWidth)
  continue;                       // 델타 = 0 (그대로)
...
const int lo = firstActive + kSmoothHalfWidth;   // 5단계 평활 구간
const int hi = lastActive  - kSmoothHalfWidth;
```

`firstActive+2` 밴드는 델타 **전량**을 받고 `firstActive+1` 은 정확히 0 이다. 5단계의 ±1 평활은 `[lo, hi]` 안쪽만 돌기 때문에 **바로 그 경계를 넘지 못해** 계단을 지우지 못한다. 6단계의 라우드니스 중립화는 `corrected` 밴드에서만 평균을 빼므로 경계 간격을 `mean` 만큼 **더 벌린다** — 5단계 주석의 "(2)" 가 이미 지목하던 기전인데, 당시 대책(평활)이 경계에는 닿지 않았다.

비발디는 80Hz 이하가 거의 없는 곡이고 설문은 저음을 원했으므로 `dev·taste < 0`(상충) → `α = 0.70` → 저역 델타가 크게 잡혔다. 델타가 클수록 계단도 그대로 커진다.

**조치 — 차단을 감쇠로 바꾼다**

1. `AdaptiveCurve.h`: `kSmoothHalfWidth = 2` 삭제, `kEdgeTaperBands = 4` 신설.
2. 3단계: 가중치 배열 `edgeW` 산출. `e = min(i - firstActive, lastActive - i)` 일 때

   | e | 0 | 1 | 2 | 3 | ≥4 |
   |---|---|---|---|---|---|
   | edgeW | 0 | 0.25 | 0.50 | 0.75 | 1 |

   선형인 이유: 폭이 정해졌을 때 이웃 밴드 간 **최대 낙차를 최소화**하는 형상이다. smoothstep 은 가운데가 더 가팔라 같은 폭에서 낙차가 1.5배 커진다.
3. 4단계: 가장자리 `continue` 제거 — 유효 밴드 전체에서 델타를 계산한다.
4. 5단계: 평활 구간을 `[firstActive, lastActive]` 전체로 넓힌다.
5. **5-b 신설**: 평활이 끝난 **뒤에** `delta[i] *= edgeW[i]`. 순서가 중요하다 — 먼저 곱하면 평활이 경사를 되뭉개 끝 밴드가 0 이 아니게 되고 끝단 보호가 깨진다.
6. 6단계: 빼는 양에도 같은 가중치를 곱한다. 균일하게 빼면 0 으로 만들어 둔 끝 밴드만 `mean` 만큼 어긋나 계단이 되살아난다.
   평균을 `Σ(L·delta) / Σ(L·edgeW)` 로 잡으면 `Σ L·(delta - edgeW·mean) = 0` 이 **정확히** 성립해 연속성과 라우드니스 중립을 동시에 만족한다.

끝 밴드의 델타는 여전히 **정확히 0** 이다 — 기준 스펙트럼을 못 믿는 끝단을 건드리지 않는다는 보호의 취지는 그대로다. 바뀐 것은 그 보호를 놓는 방식뿐이다.

**예상 효과**
경계의 최대 낙차가 `델타` 에서 `델타/4` 로 떨어진다. 이번 실측(3.60dB)이면 **0.90dB** — 커브 자체의 밴드 간 기울기(31→63Hz 구간에서 0.7~1.2dB)와 같은 수준이라 계단으로 보이지 않는다. 덤으로 20/25Hz 도 이제 부분 보정을 받는다. 두 밴드는 31Hz 와 똑같이 저음이 빈 밴드였는데 구판은 보정을 통째로 막고 있었다.

**검증 — 현장 실측 (같은 곡, 같은 실패 입력 `source:unresolved`)**

지표는 **국소 곡률** `|g[i] - (g[i-1]+g[i+1])/2|` 을 쓴다. 상수 오프셋과 균일 기울기에 불변이라, "이웃과 어긋나 혼자 튀어나온 정도"만 정확히 잡아낸다. 기울기(셸프 전이)는 0 으로 나오고 계단만 남는다.

| | 구판 20:42:40 | 신판 20:56 |
|---|---|---|
| 25→31Hz 낙차 | **+3.60 dB** | **+0.95 dB** |
| 31Hz 곡률 | **+1.855 dB** | **+0.04 dB** |
| 최대 곡률 위치 | 31Hz (가장자리 경계) | 50Hz (감쇠 상단 무릎) |
| 최대 곡률 값 | 1.855 dB | 1.010 dB |
| 12.5k→16k 낙차 | -0.58 dB | -0.05 dB |
| 16kHz 곡률 | -0.30 dB | +0.15 dB |
| Preamp | 0.0 dB | 0.0 dB |

저역 감쇠 구간이 설계대로 선형으로 펴졌다 — 20/25/31/40Hz = `+4.14 / +5.11 / +6.06 / +6.93`, 낙차 `0.97 / 0.95 / 0.87`. 가중치 `0 / 0.25 / 0.50 / 0.75` 에 정확히 대응한다. 구판이 통째로 막던 25/31/40Hz 가 이제 부분 보정을 받는다.

**남은 것 — 50Hz 곡률 (2곡에서 재현)**
감쇠가 1 로 포화하는 무릎이다. `firstActive = 0`(20Hz) 일 때 무릎은 항상 `index 4 = 50Hz` 에 선다 — 프로그램과 무관한 **구조적 위치**이고, 실제로 성격이 정반대인 두 곡에서 같은 밴드에 잡혔다.

| 곡 | 50Hz 곡률 | 그 대역 델타 `d` | 이론 무릎 `d/(2W)` | 잔여(델타 자체 형상) |
|---|---|---|---|---|
| 비발디 (저역 결핍) | **+1.01 dB** | +3.30 | 0.41 | 0.60 |
| 쌈디 (저역 과다) | **-1.40 dB** | -3.71 | 0.46 | 0.94 |

부호가 델타 부호를 따라간다 — 감쇠 형상이 원인인 성분의 서명이다. 다만 크기는 두 곡 모두 **이론값의 2~3배**이고, 초과분은 델타 자체의 롤오프다: 비발디는 60~80Hz 부터 실제 저역 내용이 시작돼 편차가 거기서 빠르게 줄고, 쌈디는 808 기음이 50Hz 부근에 협대역으로 서 있어 그 밴드만 깊게 깎인다. 즉 **내 감쇠가 만드는 몫은 0.41~0.46 dB 로 일정**하고, 나머지는 제어식이 곡을 정직하게 따라간 결과다.

판단: 애초 신고된 계단은 3.60 dB 였고 지금 내 코드가 만드는 몫은 0.46 dB — 한 자릿수 아래다. 협대역 성분은 5단계 ±1밴드 평활이 이미 한 번 눌렀고, 더 누르면 실제 스펙트럼 피크에 대한 응답까지 함께 죽는다. **선형 W=4 유지.**

`W` 를 넓히면 무릎 곡률은 `d/(2W)` 로 함께 줄지만(W=6 이면 0.32), 양 끝 12밴드가 부분 보정에 묶여 보정 권한을 너무 많이 잃는다. smoothstep 은 무릎을 없애는 대신 가운데 낙차가 1.5배(0.95 → 1.31)로 커져 상쇄다. 재발 시 후보는 이 두 가지다.

**검증 — 빌드 게이트**
- GATE 1 `run_curve_equiv.bat` — `cases=82160 mismatched=0 / RESULT: IDENTICAL (bit-exact)`. `LocalCurve` 미변경 확인.
- GATE 2 `run_gain_probe.bat` — `[PASS] 제어식 검증과 전수 스윕 모두 통과`, `예산 초과: 구판 2942건 / 신판 0건`.
- 제어식 성질은 보존된다. 추가된 것은 밴드별 가중치 `edgeW ∈ [0,1]` 뿐이라 `|delta|` 가 줄기만 하고 부호는 불변이다 — 동조 약보정 / 상충 강보정 / 상한 / 에너지 예산 어느 것도 새로 위반될 수 없다.

**되돌리는 법**
`kEdgeTaperBands = 0` 으로 두면 안 된다(0 나눗셈). 구판 동작이 필요하면 `edgeW` 를 `e < 2 ? 0.f : 1.f` 로 바꾸고 5단계 구간을 `firstActive+2 … lastActive-2` 로, 6단계의 `edgeW[i] * mean` 을 `mean` 으로 되돌린다. 되돌리면 계단이 그대로 돌아온다.

### 검증 기록

#### V1. 동조/상충 비대칭 — 현장 실측 (2026-09-20)

v0.1.1 의 존재 이유인 `α` 비대칭이 **실제 재생에서** 도는지 확인한 기록이다. 게이트는 합성 입력이라 "식이 맞다"만 증명한다. 진짜 곡 두 개로 "식이 실제로 걸린다"를 따로 확인했다.

**방법** — 성격이 정반대인 두 곡을 같은 설문(=같은 `taste`)으로 연속 재생하고, 엔진에 나간 `config.txt` 를 각각 정착 후 읽었다. 둘 다 `source: unresolved`(메타데이터 해석 실패)라 **입력 조건까지 동일**하다. 바뀐 변수는 곡의 스펙트럼 하나뿐이다.

델타 추출은 **20Hz 를 기준점**으로 삼는다. 가장자리 감쇠 때문에 `edgeW[0] = 0`, 즉 20Hz 는 언제나 순수 `taste` 다. 따라서
```
delta[i] = (obs[i] - obs[20Hz]) - (taste[i] - taste[20Hz])
```
로 `NormalizeForPlayback` 의 상수 오프셋이 소거된다. 배율은 반대쪽 끝밴드(20kHz, 역시 `edgeW = 0`)로 확인해 `k = 0.980` — 사실상 1 이므로 그대로 읽어도 된다. `taste` 는 `tools/curve_match_v011.exe` 가 2052 후보 중 최소제곱으로 식별했다(상위 5개가 `bass_heavy` + `treble_warm` 에서 전부 일치).

**결과 — 저역(`taste > 0`, 저음 선호)**

| Hz | taste | 비발디 delta | 쌈디 delta |
|---|---|---|---|
| 20 | +1.70 | 0 (기준) | 0 (기준) |
| 31 | +1.66 | **+1.96** | **-1.01** |
| 40 | +1.59 | **+2.90** | **-2.47** |
| 50 | +1.47 | **+3.30** | **-3.71** |
| 63 | +1.26 | **+1.77** | **-2.07** |

같은 취향에서 저역 보정 **부호가 통째로 뒤집혔다.** 저역이 빈 비발디는 `dev < 0 × taste > 0` → **상충** → 끌어올리고, 808 이 실린 쌈디는 `dev > 0 × taste > 0` → **동조** → 되당긴다. 설계 원문(*"저음이 강한데 저음을 좋아한다 그러면 그대로 냅두거나 조금만"*) 그대로다.

크기도 역산이 성립한다. `|delta| = α·|dev'|` 이므로 50Hz 에서
- 비발디 `0.70 × |dev'| = 3.30` → 기준보다 **6.2 dB 부족**
- 쌈디 `0.25 × |dev'| = 3.71` → 기준보다 **16.3 dB 과다**

쌈디는 16.3 dB 나 과한데도 3.71 dB 만 깎인다 — 곡의 저음 개성 중 12.6 dB 를 그대로 남긴다. **동조에서 약보정이 실제로 걸린 증거다.** `dev` 자체는 관측 불가라 이 역산은 정황이고, 비율의 엄밀한 증명은 아래 게이트가 맡는다.

**결과 — 고역(`taste < 0`, 고음 기피)**

| Hz | taste | 비발디 delta | 쌈디 delta |
|---|---|---|---|
| 8000 | -3.75 | **+1.27** (동조) | **-0.62** (상충) |
| 12500 | -3.88 | **+1.04** (동조) | -0.16 |
| 16000 | -3.84 | **+0.95** (동조) | +0.17 |

어두운 녹음인 비발디는 고역을 **더 깎지 않는다**(+로 되돌림 = 어둠 유지, 동조). 밝은 쌈디는 깎는다(상충). 저역과 독립적으로 같은 법칙이 돈다.

**결과 — 취향 보존**
`taste` 가 평탄한 800Hz~1.25kHz 구간에서 `|delta| ≤ 0.47 dB`. 보정이 중역을 흔들지 않는다.

**교차 검증 — GATE 2 (`run_gain_probe.bat`)**
```
kAlphaAgree=0.25  kAlphaOppose=0.70  kAgreeScaleDb=3.00
[OK] A1 취향 보존 : dev=0 일 때 |delta| 최대 0.0000 dB
[OK] A2 비대칭    : 평균 |delta| 동조 0.749 < 무취향 1.269 < 상충 1.789 (비 2.39x)
[OK] A3 보정 방향 : 편차를 되돌리는 방향을 벗어난 밴드 0개
[OK] A3b 상충 실감: 곡이 센 대역 7개 중 상충이 중립보다 덜 깎은 밴드 0개
```
비가 명목값 `0.70/0.25 = 2.80x` 가 아니라 **2.39x** 인 것은 오류가 아니다. `agree = tanh(dev·taste / kAgreeScaleDb²)` 가 연속 함수라 판정이 애매한 밴드는 두 α 사이에 놓인다 — 평균을 내면 양 끝값보다 안쪽으로 모인다. 계단 판정(±1 이진)이었다면 정확히 2.80x 가 나왔겠지만, 그 경우 A4 연속성 검사가 깨진다.

**결론: 비대칭은 식(게이트)과 현장(실측) 양쪽에서 확인됐다.** v0.1.1 의 핵심 주장은 검증 완료.

## [2026-09-20 밤] 저역 국소 곡률 상한

### 알고리즘 변경

#### A6. 저역 적응 델타에 국소 곡률 상한을 건다

**무엇이**: `ComputeTasteDelta` 의 후처리가 6단계(라우드니스 중립화 + 클램프)에서 끝나던 것을, 7단계(저역 곡률 상한) + 8단계(중립화 재실행)까지로 늘렸다.

```
기존:  원델타 → ±1밴드 평활 → 가장자리 감쇠 → 중립화 → 클램프
신규:  원델타 → ±1밴드 평활 → 가장자리 감쇠 → 중립화
                → 저역 곡률 상한  ← 추가
                → 중립화 재실행 + 클램프  ← 추가
```

상한 자체는 세 줄이다. 31Hz~100Hz 의 각 밴드에서

```
avg      = (delta[i-1] + delta[i+1]) / 2
res      = delta[i] - avg
delta[i] = avg + clamp(res, ±kLowCurvatureLimitDb)      // 1.00 dB
```

신규 상수: `kLowCurvatureLimitDb = 1.0f`, `kLowCurvatureLoHz = 31`, `kLowCurvatureHiHz = 100` (`AdaptiveCurve.h`).

**왜**: E6 을 고친 뒤에도 50Hz 한 밴드가 이웃과 어긋나는 성분이 남았고, 성격이 정반대인 두 곡에서 같은 밴드에 재현됐다(비발디 +1.01dB / 쌈디 −1.40dB, 부호는 그 대역 델타의 부호를 따라간다). 사용자 보고는 *"너무 부드럽지 않게 툭 튀어 나와 있는거 있긴하네"* 였다.

원인이 두 겹이다.
1. 가장자리 감쇠가 1 로 포화하는 **무릎**이 `firstActive = 0` 일 때 항상 `index 4 = 50Hz` 에 선다. 이건 곡과 무관한 구조적 위치다. 이론 기여는 `|delta| / (2·kEdgeTaperBands)` 로, 실측 델타 −3.71 에서 0.46dB.
2. 나머지(0.94dB)는 델타 자체의 형상이다 — 808·킥의 기본파가 그 근처에 좁게 몰려 있어서 제어식이 정직하게 따라간 몫이다.

즉 (2)는 제어식이 **제대로 일한 결과**라서 α 나 데드존을 건드려 없앨 것이 아니다. 필요한 것은 "옳은 보정의 모양만 다듬는" 장치였다.

**왜 곡률인가**: `|delta[i] − (delta[i−1] + delta[i+1])/2|` 는 공통 오프셋과 균일한 기울기에 대해 0 이다. 셸프도, 가장자리 경사도, 곡 전체의 기울기도 걸리지 않고 **한 밴드만 이웃과 어긋난 성분**만 남는다. 사용자가 본 "툭 튀어나옴" 과 정확히 같은 양이다. 그리고 `|res| ≤ 상한` 이면 `delta[i] = avg + res = 원래 값` 이라 **통과 시 완전한 항등**이다 — 개입하지 않을 때 아무것도 바꾸지 않는다.

**왜 1.00 dB 인가**: (1)의 구조적 성분 0.46dB 위, 실측된 이탈 1.40dB 아래. 이보다 낮추면 불가피한 무릎 성분까지 계속 건드려 저역 보정이 조금씩 새어나간다. 쌈디 50Hz 실측에 적용하면 −3.71 → −3.27, **0.44dB 만 물러난다.** 808 보정은 살아 있고 '한 밴드만 튀어나온' 성질만 사라진다.

**왜 취향 커브에는 걸지 않는가**: 설문이 말한 음색은 사용자가 고른 목표다. 그 모양을 이 계층이 다듬을 권한이 없다. (덧붙여 `LocalCurve` 의 저역은 LowShelf 단독이라 애초에 곡률을 만들지도 않는다.)

**왜 중립화를 두 번 부르는가**: 상한이 델타를 움직이면 라우드니스 중립이 깨진다. 같은 연산을 그대로 한 번 더 건다 — 첫 호출이 이미 0 을 맞춰 놓았으니 두 번째가 빼는 양은 상한이 움직인 몫뿐이고, 그래서 수렴 반복이 필요 없다. 다만 중립화가 빼는 `edgeW·mean` 은 감쇠 무릎에서 꺾이므로 `mean/(2·kEdgeTaperBands)` 만큼의 곡률을 되돌려 놓는다 — 게이트가 허용 0.30dB 여유를 두는 근거가 이것이다.

**왜 스냅샷으로 읽는가**: 상한을 제자리에서 훑으면 `i` 의 결과가 `i+1` 의 입력이 되어 처리 순서가 결과를 바꾸고, 낮은 쪽에서 눌린 값이 위로 전파돼 저역 전체가 조금씩 평탄해진다. 밴드마다 독립 판정이어야 한다.

**가장자리 밴드는 건너뛴다**: `edgeW[i] == 0` 인 밴드는 5-b 가 정확히 0 으로 만들어 둔 끝단이다. 여기를 `avg` 쪽으로 당기면 E6 에서 고친 계단이 반대 방향으로 되살아난다.

##### 기각한 대안 — 왜 이것들이 아닌가

같은 증상에 네 가지 후보가 있었고 전부 기각했다.

| 후보 | 기각 이유 |
|---|---|
| (a) 저역 매크로 보정 (저역을 한 덩어리로 묶어 평균만 적용) | 저역 **내부의 대비**를 통째로 없앤다. 40Hz 와 100Hz 는 다른 악기다. "저음이 뭉갠다" 로 돌아온다. v0.1.2 후보로 남김 |
| (b) `kEdgeTaperBands` 4 → 6 | 무릎을 50Hz 에서 80Hz 로 **옮길 뿐** 없애지 못하면서, 100Hz 까지 보정을 약화시킨다 |
| (c) 감쇠를 smoothstep 으로 | 같은 폭에서 가운데 낙차가 1.5배 커진다 (E6 에서 이미 기각한 이유 그대로) |
| (d) 5점 평활 | 전 대역의 **의도된** 모양을 같이 깎는다. 저역만의 문제에 전역 처방 |

곡률 상한만이 **원인 성분에만 비선형으로** 작용하고 나머지 통과 시에는 항등이다.

**음색 영향**: 저역이 좁게 몰린 곡(힙합·EDM)에서 50Hz 부근의 보정이 최대 0.4~0.5dB 물러난다. 그 외 모든 곡에서 변화 없음(게이트 A5c 가 이것을 보증한다).

**되돌리는 법**: `AdaptiveCurve.cpp` 의 7·8단계 블록을 지우고 6단계 끝의 `neutralize()` 만 남긴다. 헤더의 상수 3개와 게이트 A5/A5b/A5c, 스윕의 `lowCurvBad` 도 같이 지울 것.

##### 게이트 (`tools/gain_probe_main.cpp`, GATE 2)

세 개를 새로 넣었다. **위아래를 모두 고정한다** — 상한만 보면 "델타를 전부 0 으로 만들어도 통과" 가 되고, 하한만 보면 상한이 풀린 것을 못 잡는다.


전수 스윕(15360 케이스)에도 같은 지표를 달았다: `최대 저역 곡률 1.000dB @ 50Hz`, 초과 0건.

**합성 융기의 폭이 핵심이었다.** 폭 1~2밴드는 5단계 ±1밴드 평활이 이미 평탄한 고원으로 펴버려서 곡률이 거의 안 생긴다(단일 밴드 스파이크는 `(0 + d + 0)/3` 이 이웃 둘과 같은 값이 된다). 상한이 실제로 일할 자리는 **폭 3~4밴드** — 평활 커널보다 넓어서 살아남고, 그러면서도 한 밴드가 이웃 대비 꺾인다. 게이트를 단일 밴드 스파이크로만 짰다면 상한이 한 번도 안 걸린 채 초록으로 통과했을 것이다.

**A5c 의 기준을 실측 후에 고쳤다 — 기록해 둔다.** 처음에 `상한 × 0.50 = 0.50dB` 로 잡았고 실측 0.710dB 로 실패했다. 확인해 보니 상한이 개입한 게 아니라 (1)의 무릎 성분 + α·클램프의 꺾임이 더해진 **구조적** 값이었다(+9dB 기울기에서 델타 ≈ 3.9 → 무릎만 3.9/8 = 0.49dB). A5c 가 물어야 할 것은 "곡률이 작은가" 가 아니라 **"상한이 물지 않았는가"** 이므로 기준을 `상한 − 0.10 = 0.90` 으로 바꿨다. 상한에 걸리면 곡률이 정확히 상한 근처에 고정되므로, 그 아래로 여유가 남아 있는 것이 곧 '개입하지 않았다' 의 증거다. **기준을 느슨하게 만든 변경이므로 근거를 남긴다** — 이 값을 더 낮추는 것은 곡률 상한의 일이 아니라 `kEdgeTaperBands` 의 일이다.

##### 채택하지 않은 별도 제안 — 트랙 단위 고정(freeze)

### 알고리즘 변경

#### A7. 기준 스펙트럼: 4곡 실측 평균 → 해석적 3구간 곡선

**무엇이**: `LocalCurve::ReferenceShapeDb()` 가 `10·log10(kRefBlob)` + ±2밴드 이동평균을 돌려주던 것을, 무릎 2개와 기울기 3개로만 정의되는 3구간 직선으로 바꿨다.

```
40Hz 아래   : -10.0 dB/oct   (마스터링 하이패스)
40 ~ 200Hz  :  +1.5 dB/oct   (완만한 어깨)
200Hz 위    :  -3.0 dB/oct   (롤오프)
→ 코어(100Hz~5kHz, 밴드 7~24) 평균을 0 으로 정규화
```

1/3 옥타브 31밴드는 밴드 인덱스가 곧 로그축이다 — `x = log2(f/1000) = (i-17)/3` 이 **정확히** 성립한다(밴드 17 = 1kHz, 옥타브당 3밴드). 그래서 주파수 표 없이 무릎을 밴드 3(40Hz)·밴드 10(200Hz)에 놓을 수 있다. `LocalCurve.cpp` 에는 주파수 표가 없는데도 이 곡선이 들어간 이유가 이것이다.

결과 형상 (dB, 코어 정규화 후):

| Hz | 20 | 40 | 100 | **200** | 1k | 4k | 10k | 20k |
|---|---|---|---|---|---|---|---|---|
| ref | -7.5 | +2.5 | +4.5 | **+6.0** | -1.0 | -7.0 | -11.0 | -14.0 |

**왜 3구간인가 — 실측으로 정했다** (`tools/ltas_fit_main.cpp`, 가중 최소제곱)

| 모델 | rms 오차 | 최대 오차 |
|---|---|---|
| 2구간 (무릎 1개) | 2.126 dB | 8.529 dB @ 20Hz |
| **3구간 (40Hz 하단 무릎, -10dB/oct)** | **0.797 dB** | **2.77 dB @ 40Hz** |

하단 무릎 후보 {40, 50, 63, 80Hz} 중 40Hz 가 뚜렷하게 최적이었다. **남은 최대 오차가 40Hz 에 앉았다는 게 핵심이다** — 40Hz 는 4곡 표본의 베이스라인 아티팩트가 있는 바로 그 지점(E1 에서 +3.93dB 로 측정)이다. 즉 모델은 물리(마스터링 하이패스·롤오프)를 잡고 장르를 남겨 두고 나왔다. 반올림 허용치(0.838 vs 0.854)와 핑크노이즈 대조(5.772) 도 같이 봤다.

**왜 '내 라이브러리 평균' 이 아닌가**

대안으로 개인 청취 기록(64곡)의 밴드별 경험 평균이 제안됐고, 기각했다.

| 밴드 | 출하 기준(4곡) | 이 사용자 라이브러리(64곡) | 채택한 해석 곡선 |
|---|---|---|---|
| 40Hz (1kHz 대비) | **+5.85 dB** | **-2.67 dB** | **+3.49 dB** |

- 기준을 라이브러리 평균으로 두면 **정의상 편차가 평균적으로 0 이 되어 EQ 가 조용해진다.** v0.1.1 의 설계 요구 *"노래를 완전 플랫하게 → 내 취향대로"* 와 정면으로 어긋난다.
- 64곡 한 사람의 평균은 또 다른 장르 각인이다. 40Hz 의 곡간 표준편차가 **7.19 dB** 다.
- 해석 곡선은 출하 기준의 과잉 저역을 절반만 덜어낸다. 한 라이브러리의 취향을 만인의 '정상' 으로 삼지 않으면서, 4곡 아티팩트는 제거한다.
- 장르가 들어앉을 자리가 없고(파라미터 5개), 전 사용자에게 동일하게 나가고, 개인 데이터·콜드스타트·역공학 표면이 전부 0 이다.

한편 64곡 대조는 **40Hz 범프가 표본 잡음이라는 E1 의 진단을 확증했다** (기준 +3.93 vs 경험 +0.75). 반대로 12.5kHz(+2.31 vs +2.25)와 20kHz(-7.49 vs -7.38)는 재현됐다 — 그쪽은 표본 오염이 아니라 코덱의 실제 절벽이다. 그래서 상단 무릎은 **일부러 모델에 넣지 않았다.** 저차 함수로는 20kHz 의 계단을 표현할 수 없고, 그건 기준이 할 일이 아니라 아래 A8 게이트가 할 일이다.

**`EnergyChangeDb` 는 손대지 않았다.** 그쪽은 계속 원본 `kRefBlob` 을 선형 파워로 쓴다. 음색 경로와 에너지 경로가 분리돼 있어서, `Generate()` 출력은 비트 단위로 불변이고 GATE 1 도 영향받지 않는다. `tools/localcurve_ref.cpp` / `supabase/.../curve.ts` / `tools/v010/` 의 사본도 그대로 둔다.

**음색 영향**: 모든 곡에서 저역 보정 기준이 내려간다. 40Hz 가 1kHz 대비 +5.85 → +3.49dB 이므로, 이전에는 "저음이 부족하다" 고 읽혀 부스트되던 곡이 이제 중립으로 읽힌다. 20Hz·25Hz 의 표본 아티팩트(-3.87 / -2.83dB)가 사라진다.

**되돌리는 법**: `LocalCurve.cpp` 의 `ReferenceShapeDb()` 람다를 `RefSpectrum()` 기반 `10·log10` + ±2밴드 평활로 되돌린다. 다른 파일은 손댈 것이 없다.

#### A8. 프레즌스 게이트 — 바닥 판정의 이진 계단을 부드러운 어깨로 편다

**무엇이**: `ComputeTasteDelta` 3-b 단계 신설. `presence[i] = clamp((measured[i] - floorDb) / kPresenceSoftDb, 0, 1)` 를 α 에 곱한다. `kPresenceSoftDb = 10.0f` 신설.

**왜**: 1단계의 바닥 판정(`measured > median - 40dB`)은 그 경계에서 보정을 통째로 끊는 **이진 계단**이었다 — E6 에서 가장자리 보호에 대해 고친 것과 같은 종류의 결함이 바닥 판정 쪽에 그대로 남아 있었다. 게다가 A7 로 상단 무릎을 모델에 넣지 않기로 했으므로, 코덱이 잘라낸 16k/20k 를 처리할 주체가 필요했다.

`edgeW` 로는 대신할 수 없다. **`edgeW` 는 '위치'(유효 구간의 끝)를 보고, 이 게이트는 '존재량'(사실상 비어 있는가)을 본다.** 유효 구간 안쪽이면서 비어 있는 밴드 — 첼로 독주의 31Hz, 코덱이 자른 16kHz — 는 원리상 `edgeW` 가 못 잡는다.

**음색 영향**: 실음악에서는 **항등이다**(게이트 A6a 가 이것을 보증한다 — 보정이 나가는 143밴드에서 최저 여유 +3.00dB). 발동하는 것은 바닥 근처 10dB 구간뿐이고, 그 구간은 원래 보정해 봐야 잡음만 올라오는 자리다.

**되돌리는 법**: `AdaptiveCurve.cpp` 의 3-b 블록과 4단계의 `* presence[i]` 를 지우고, 헤더의 `kPresenceSoftDb` 와 게이트 A6a/A6b/A6c 를 같이 지운다.

##### 게이트 (`tools/gain_probe_main.cpp`, GATE 2)


**A6a 는 `edgeW == 0` 인 밴드를 제외하고 잰다.** 실측 light LTAS 의 20Hz 는 중앙값보다 31dB 아래라 게이트가 0.9 로 닫히지만, 그 밴드는 5-b 가 어차피 정확히 0 으로 덮는다. 거기까지 항등을 요구하면 게이트가 아니라 LTAS 의 저역 절벽을 시험하는 꼴이 된다. **판정을 느슨하게 만든 변경이므로 근거를 남긴다.**

#### E7. 프레즌스 게이트를 '피크 기준' 으로 짰다가 정상 음악에서 게이트가 닫혔다

실측 bass-heavy LTAS 의 16kHz 는 피크보다 **44dB** 아래다. 한 밴드가 압도적으로 큰 스펙트럼(저음이 센 곡)에서 나머지가 통째로 "내용 없음" 으로 분류되어, **멀쩡한 음악에서 고역 보정이 10% 로 닫혔다.**

**이건 코드가 이미 경고해 둔 함정이었다.** `AdaptiveCurve.cpp:307` 에 v0.1.1 초판부터 이렇게 적혀 있다: *"[왜 최댓값이 아닌가] peak - 40dB 로 잡으면 한 밴드가 압도적으로 큰 스펙트럼에서 나머지 전부가 '내용 없음' 으로 분류돼 보정이 통째로 꺼져버린다."* 같은 파일에 적힌 경고를 20줄 아래에서 그대로 밟았다.

**조치**: 새 기준점을 만들지 않고, 이미 있는 **중앙값 기준 바닥**(`median - kFloorRangeDb`)의 **부드러운 어깨**로 게이트를 재정의했다. `kPresenceRangeDb` 는 만들었다가 삭제했다. 덤으로 바닥 판정의 이진 계단(A8)도 같이 없어졌다.

**교훈**: 새 임계값을 도입하기 전에 **같은 파일 안에 이미 있는 판정 기준을 먼저 찾을 것.** 한 모듈에 바닥을 재는 방식이 둘이면 그중 하나는 곧 틀린다.

**증상**: E4 는 *"`track` 테이블 284행 중 `genre` 가 채워진 행 0개 → 23개 장르 테이블은 죽은 코드였고 모든 사용자는 스마일 커브를 받고 있었다"* 고 적었다.

### 알고리즘 변경

#### A9. AI 자유 프롬프트에서 장르 필드 삭제

**무엇이**: `MainWindow.cpp:805` 가 `m_currentGenre` 를 `GenerateAllBandsEQ` 에 넘기던 것을 삭제. `AIClient::GenerateAllBandsEQ` / `CallProxyAPI` 시그니처에서 `genre` 인자를 빼고, HTTP 바디의 `{"genre", genre}` 도 제거했다.

**여기 장르는 '장식' 이 아니었다.** 자동 경로(`LocalCurve::Generate` 의 `(void)genre`)와 달리 실제로 모델 입력까지 도달했다: `AIClient.cpp` → `generate-eq/index.ts:75` `sanitize(body.genre, 200)` → **`:116` `<genre>${genre || "Unknown"}</genre>`** 로 Gemini 프롬프트에 문자열 보간. 그래서 "지우면 아무것도 안 바뀐다" 는 논거는 쓰지 않는다.

**왜 지우는가**

- **같은 문장이 곡마다 다른 뜻이 됐다.** `track_meta` 90행 중 장르 보유 67행(74%). 나머지 26% 는 `<genre>Unknown</genre>` 을 받는다. 사용자가 두 곡에 똑같이 "보컬 좀 살려줘" 를 쳐도 한쪽만 장르 조건부 커브가 나오고, **그 차이가 화면에 전혀 드러나지 않는다.** 정보 패널은 `---` 만 찍는다.
- **그 축을 정하는 게 음악이 아니다.** 장르의 출처는 iTunes `primaryGenreName` 이고, 그건 곡이 아니라 앨범/아티스트 단위 한 단어 라벨이다. 무엇보다 그 라벨이 붙느냐 마느냐를 결정하는 건 **미디어 플레이어가 그 순간 표시하던 문자열**이다 — 아래 비발디 케이스(같은 곡, 4초 간격, 유튜브가 제목을 영어판→한글판으로 바꿨다는 이유만으로 `Classical` → `""`)가 그대로 증거다.
- **락 없는 교차 스레드 읽기였다.** `m_currentGenre` 는 곡 해석 detached 스레드(`:1528`)가 쓰고 AI 워커 스레드가 `this` 로 실시간 읽었다. 제목/아티스트는 바로 위 `:716` 에서 `SnapshotCanonical()` 로 스냅샷을 뜨는데 장르만 예외였다. 재시도 루프(백오프 `{0,3000,10000}`)라 읽기 시점이 최대 13초 흩어진다.

**반론도 기록해 둔다 (기각한 근거)**: "베이스 좀 더" 가 EDM 에서 40~60Hz, 록에서 80~120Hz 를 뜻한다는 어휘 해석 문제는 실측 스펙트럼이 원리상 답할 수 없고 장르가 바로 그 사전이라는 반론이 있다. 기각한 이유는 두 가지다. (1) 장르가 존재하는 74% 는 **정의상 iTunes 가 해석에 성공한 곡**, 즉 LLM 이 이미 그 곡을 알고 있을 확률이 가장 높은 경우다. 장르가 가장 절실한 미해석 26% 에서는 장르도 같이 없다 — 한계 기여가 가장 낮은 자리에만 존재한다. (2) 장르가 Gemini 출력을 실제로 얼마나 움직이는지에 대한 A/B 실측이 없다. **측정되지 않은 이득과, 곡마다 조용히 갈리는 관측된 비일관성을 맞바꿀 수는 없다.**

**서버는 건드리지 않는다 — 배포 없음.** `index.ts:75` 는 `body.genre` 를 계속 읽지만 `sanitize()` 가 문자열 아닌 값(여기서는 `undefined`)을 `""` 로 만들므로, v0.1.1 의 모든 요청은 `<genre>Unknown</genre>` 이라는 **상수**를 받는다. 상수는 곡마다 다른 결과를 만들지 않는다 — 축은 이걸로 끊긴다. 서버를 같이 고치면 설치된 v0.0.2 / v0.1.0 클라이언트의 음색이 즉시 바뀌므로(A1 에서 `curve.ts` 를 동결한 것과 같은 이유) 하지 않는다.

**음색 영향**: 장르가 있던 74% 의 **자유 프롬프트 결과**만 바뀐다. 자동 경로는 이미 장르를 안 쓰므로 영향 없다. 방향은 "모든 곡이 미해석 곡과 같은 대접을 받는다" 쪽이다.

**되돌리는 법**: `AIClient.h/.cpp` 의 `genre` 인자 3곳과 바디 필드 1곳을 복원하고, `MainWindow.cpp:805` 에 `m_currentGenre` 를 되돌린다. 단 되돌린다면 `:716` 옆에서 스냅샷을 떠야 한다 — 멤버를 라이브로 읽는 형태로는 복원하지 말 것.
